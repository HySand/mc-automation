# 合规多站点自动顶贴

## Goal

为一个 Minecraft 服务器在 KLPBBS 与 MineBBS 上的宣传帖提供可审计、可扩展的自动化：在公开版规允许的范围内签到、获取和消费官方站内资源，并按 KLPBBS 排名资格或 MineBBS 固定间隔顶贴，从而降低人工维护成本与封号风险。

## Background

- 当前仓库只有 Trellis 脚手架，没有可复用业务代码。
- 用户指定 `HySand/klpAutomation` 为 KLPBBS 参考实现。该项目使用 Python 3.11、HTTP 会话、BeautifulSoup 与每小时运行的 GitHub Actions，包含登录、签到、回复、提升卡和代理刷推广访问。
- 默认模式中的代理刷访问、虚假流量及验证码令牌生成均不纳入本项目；KLPBBS 使用
  `cloudscraper` 建立兼容会话，推广代理仍仅用于独立、显式配置的 IP 字面量目标。
- MineBBS 服务器宣传版规页面标注为 2025-08-02 版本，最后编辑于 2026-07-03：宣传版禁止回帖；自己的帖子只能使用官方紫晶或金粒顶贴卡。每日签到可得 1 紫水晶，紫晶卡售价 1 紫水晶，金粒卡售价 100 金粒且每日限购 1 张，道具购买后 7 天失效。
- KLPBBS 服务器版规首帖最后编辑于 2025-07-27：同一宣传帖每日仅可自回复顶贴一次，提升卡不受该次数限制；禁止灌水、大小号刷评分，并禁止发帖时使用代理或 IDC 机房登录地点。
- 首期唯一运行环境是 GitHub Actions。公共 Runner 的机房出口可能触发站点风控，因此系统必须失败关闭而非规避安全机制。

## Requirements

### R1 — 合规与安全边界

- 只执行站点公开提供且规则允许的正常账号操作。
- 默认模式不绕过验证码、WAF、访问控制、封禁、限流或其他反自动化机制。
- 默认模式不使用代理池、虚假账号、伪造点击/浏览量、刷评分或验证码服务。KLPBBS
  仅使用 `cloudscraper` 提供的 HTTP 会话兼容能力；推广代理只能发往用户显式配置的
  公网 IP 字面量目标，不能把站点域名交给代理端解析。
- 检测到验证码、安全挑战、规则性拒绝、登录限制、页面结构异常或排名无法可靠解析时，停止该站点的后续消费操作并报告；另一站点仍继续运行。
- 网络瞬时错误只做有限次数指数退避；安全挑战、权限错误与规则性拒绝不重试。

### R2 — MVP 范围与多站点边界

- MVP 管理一个 Minecraft 服务器，每个站点仅一个账号和一个宣传帖。
- 提供统一站点适配器契约：认证、签到、资源/库存查询、排名检查、顶贴资格判断、购买道具、执行顶贴与结果解析。
- 首期实现 KLPBBS 与 MineBBS 适配器；内部配置可在未来扩展多账号/多帖子，但 MVP 不提供该功能。

### R3 — 凭据与配置

- 两站凭据、帖子 ID 及站点开关通过 GitHub Actions Secrets/Variables 注入。
- 密码、Cookie、令牌、表单校验码及其他秘密不得提交到仓库、写入状态缓存或出现在普通日志和 Job Summary 中。
- 登录失败或疑似风控后，不执行该账号的签到、购买或顶贴。

### R4 — 调度、状态与幂等

- GitHub Actions 每小时定时运行，并支持 `workflow_dispatch` 手动触发；两种入口调用同一业务流程。
- 使用 workflow concurrency 防止同一仓库内任务并发消费。
- 跨临时 Runner 的状态通过 GitHub Actions Cache 保存，只记录最近动作与付费冷却；缓存缺失时从站点页面保守重建，无法重建则跳过有副作用的动作。
- 所有自然日规则使用 `Asia/Shanghai`；KLPBBS 同一帖子两次付费顶贴至少间隔 1 小时，MineBBS 两次成功顶贴至少间隔 16 小时。
- 每次运行只允许每站完成一个购买/使用事务，避免重入或解析错误导致连续消费。
- 安全挑战每次出现都只终止该站点的本轮操作并告警；不跨运行累计挑战次数，也不写入暂停标记，后续调度继续重新尝试。

### R5 — 顶贴触发与消费策略

- KLPBBS 每小时检查目标帖在服务器宣传版块中的位置，仅在排名大于可配置阈值（默认 8）时顶贴；MineBBS 不使用排名作为顶贴资格。
- 用户允许自动消费全部可用站内货币：余额保留线为 0，不设置消费预算。
- 仍须遵守站点官方限购、至少 1 小时付费冷却、每次运行单事务和站点返回的其他限制。
- 优先使用未过期库存；需要购买时只购买本次立即使用的一张官方顶贴道具。
- 资源不足时安全跳过，不尝试通过非官方方式获取资源。

### R6 — MineBBS 策略

- 只对用户自己的目标帖操作，绝不通过回复顶贴。
- 可执行每日签到并读取紫水晶、金粒与官方顶贴卡库存。
- 距离上次成功顶贴满 16 小时时，优先使用已有卡；否则优先购买紫晶顶贴卡，紫晶不足时购买金粒顶贴卡。
- 遵守金粒卡每日限购 1 张和道具 7 天有效期。
- “发布有效免费资源以获得宣传权限”必须由用户真实创作并人工发布、审核，不纳入自动化。
- MineBBS 不再以帖子排名作为顶贴资格；使用 `MINEBBS_BUMP_INTERVAL_HOURS` 配置，默认 16 小时。签到仍每次运行执行，只有距离上次成功顶贴达到间隔后才检查库存、购买并使用道具。

### R7 — KLPBBS 策略

- 只对用户自己的目标帖操作。
- 可执行官方签到以及无需伪造流量、评分或第三方访问的站内任务。
- 不提供回复顶贴路径；排名大于阈值且付费冷却结束时，优先使用已有提升卡，否则自动购买一张并立即使用。
- GitHub Actions 的普通网络访问必须通过 Cloudflare WARP 全隧道路由；WARP 未连接或出口检查失败时终止任务，不回退 Runner 原始出口。

### R8 — 可观测性与通知

- 每次运行输出结构化结果，包含站点、帖子、动作、状态、非敏感原因和时间。
- 状态至少区分 `success`、`skipped`、`insufficient_resources`、`manual_intervention` 与 `technical_failure`。
- MVP 使用 GitHub Actions 日志、Job Summary 与工作流失败通知，不接入外部消息渠道。
- 每次消费记录币种、金额、道具、关联帖子和站点返回结果，但不得记录秘密。

### R9 — 浏览器挑战与推广任务

- `MINEBBS_ESA_SLIDER_ENABLED` 默认关闭；开启时仅允许对 GET/HEAD 的 Alibaba ESA 滑块挑战启动可见 Chromium，挑战未清除时必须失败关闭。
- ESA resolver 只读取 `#aliyunCaptcha-sliding-slider` 与轨道元素的 DOM 边界，计算滑到末端的距离并生成平滑鼠标轨迹；不得截图交给 AI、调用模型估算坐标或伪造验证 token。
- 滑块或轨道缺失、尺寸异常、`CloakBrowser` 或 Chromium 不可用或拖动后挑战仍存在时，使用新浏览器/profile 继续下一次尝试；每次 Action 最多 3 次，全部失败后转 `manual_intervention`，POST 不重放。
- 若 MineBBS 403 呈现 Cloudflare managed-challenge Turnstile 而非 ESA，仅允许在已分类为活动挑战的 Frame 内，对唯一可见的标准 checkbox/label 执行一次 DOM 几何点击；缺失、隐藏或歧义控件继续失败关闭，不调用 AI、不猜坐标、不伪造 token。
- KLPBBS 可自动发现并领取官方推广任务，从参考项目使用的公开来源动态获取 HTTP 代理，通过不同代理直接访问经 KLPBBS 适配器同源校验的推广链接、轮询任务状态并在明确完成后领奖。
- 普通请求（包括代理源下载、推广任务申请、状态检查和领奖）走 WARP；只有最终推广链接点击使用显式动态 HTTP 代理，不继承 WARP 的应用层代理环境。
- 代理点击会话不携带登录 Cookie、账号凭据、CSRF token 或原站 Referer。
- 推广访问按最多 20 个 worker 的有界批次执行，批次间带固定间隔；代理格式经过校验和去重，每个代理每轮最多使用一次，代理源或单个代理失败互不影响，不关闭 TLS 校验。Discuz 计数所需跳转只允许手动跟随最多 3 次严格同源地址，跨域跳转必须拒绝。任务不设置固定访问次数，每批后以任务页实际进度为准，直到完成领奖或代理池耗尽。
- 推广访问不携带认证状态；推广链接由 KLPBBS 适配器在调用代理访问器前执行严格同源校验。

### R10 — 授权靶场喜欢适配器

- `WDSJFWQ_ENABLED` 和 `MCLISTS_ENABLED` 默认关闭；如启用，仍必须使用独立配置的站点 URL，并在页面控件不明确时失败关闭。
- 每个适配器只处理一个站点页面：`https://www.wdsjfwq.com/server-1991/vote.html` 或 `https://www.mclists.cn/server/9969.html`，可通过环境变量覆盖为同一授权靶场的 HTTP(S) 页面。
- 适配器先识别明确的“已喜欢”状态；否则只提交唯一发现的“点我喜欢/点赞/喜欢”链接或表单。缺少、重复或含糊的控件必须失败关闭。
- 站点请求继续使用受保护的私网传输，不使用代理、验证码服务、指纹伪装或通用 WAF 绕过。

## Acceptance Criteria

- [ ] AC1（R1/R3）：缺失凭据、登录失败、验证码、安全挑战或登录受限时，该站点不执行任何消费动作，输出不含秘密的人工介入结果。
- [ ] AC2（R4/R5/R6）：重复或并发触发不会绕过 KLPBBS 1 小时冷却或 MineBBS 16 小时间隔，同一个资格判断周期每站最多发生一次购买/使用事务。
- [ ] AC3（R2）：KLPBBS 与 MineBBS 可分别启停；任一适配器失败不会阻止另一适配器运行。
- [ ] AC4（R8）：运行结果能区分成功、合规跳过、资源不足、人工介入和技术失败，并生成 Job Summary。
- [ ] AC5（R1）：默认模式不存在代理池、虚假流量、自动验证码、限流绕过或自动解封
  逻辑；`cloudscraper` 仅用于 KLPBBS 认证传输，动态代理仅能在显式启用的 KLPBBS 推广链接点击流程中使用。
- [ ] AC6（R3）：凭据和会话秘密不进入版本控制、状态缓存、普通日志或 Job Summary。
- [ ] AC7（R1）：瞬时网络错误有限重试；安全挑战、权限错误与规则性拒绝不重试。
- [ ] AC8（R4/R5/R6）：KLPBBS 排名不大于阈值 8 或排名解析失败、任一站点间隔未结束、状态无法安全重建时不会消费资源。
- [ ] AC9（R4）：定时与手动工作流使用同一执行与幂等逻辑，并在全新 Runner 上可启动。
- [ ] AC10（R4）：状态缓存只记录付费冷却等必要业务时间戳，不记录挑战次数或暂停标记；缓存缺失时不会盲目执行有副作用动作。
- [ ] AC11（R6）：MineBBS 适配器没有回复路径，能够执行签到、余额/库存检查、官方卡片购买与使用流程。
- [ ] AC12（R7）：KLPBBS 适配器、配置和工作流均没有回复路径，只通过官方提升卡顶贴。
- [ ] AC13（R5）：余额保留线为 0，库存优先；余额不足时跳过且不触发非官方资源获取。
- [ ] AC14（R1/R4）：WAF、滑块或安全拦截夹具被识别为 `manual_intervention` 并终止本轮；下一次独立调度仍会尝试，不存在持久暂停分支。
- [ ] AC15（R5/R6）：KLPBBS 仅在目标帖排名大于阈值 8 后顶贴；MineBBS 不查询排名，并仅在距上次成功顶贴满默认 16 小时后执行顶贴事务。
- [ ] AC16（R9）：MineBBS ESA 浏览器挑战只在显式启用 `MINEBBS_ESA_SLIDER_ENABLED` 后对 GET/HEAD 最多执行 3 个独立浏览器尝试，任一次成功即停止，且不调用 AI；推广点击使用独立无凭据代理传输。
- [ ] AC17（R9）：KLPBBS 推广任务可以处理可领取、进行中、已完成领奖和未知页面；动态代理源逐个失败隔离，代理经过校验去重且每轮只用一次，点击采用最多 20 个 worker 的有界批次，并且代理请求不携带认证状态；只手动跟随 Discuz 计数所需的有界同源跳转，完成只以任务页实际进度为准。
- [ ] AC18（R9）：ESA resolver 只依据固定 DOM 几何拖动并在挑战清除后同步会话；默认模式、元素缺失或验证失败时保持 `manual_intervention`。
- [ ] AC19（R10）：两个喜欢适配器可独立启停，只在授权私网靶场解析后运行；已喜欢时跳过，唯一链接/表单成功时报告成功，任何模糊页面均不提交。
- [ ] AC20（R9）：Cloudflare Turnstile Frame 不会被误判为正常页面；仅唯一可见控件获得一次带平滑接近轨迹的点击，控件缺失或歧义时无点击且保持 `manual_intervention`。

## Out of Scope

- KLPBBS 官方推广任务之外的代理刷点击/浏览量、批量注册、虚假账号或大小号刷评分。
- 真实第三方公网服务的 CAPTCHA/WAF 令牌生成、`cloudscraper` 之外的指纹伪装或封禁规避。
- ESA 元素缺失或未能清除时的截图模型识别、坐标猜测、token 伪造、POST 重放或人工感知替代。
- 所有自动论坛回复、回复顶贴、无意义灌水或诱导评价。
- 自动创作并发布 MineBBS 宣传权限所需资源。
- 外部通知服务、Web 管理界面、多服务器、多账号、多帖子及首期之外站点。

## Resolved Decision

- GitHub Actions 的普通请求统一通过 Cloudflare WARP 全隧道路由，并在运行前验证 WARP 出口；验证失败时终止。
- 采用参考项目的动态公开 HTTP 代理源，仅将 KLPBBS 适配器校验过的同源推广链接交给代理点击。旧的公网 IP 中继地址和 `X-MC-Automation-Target` marker 校验已取消。
- 代理点击使用独立、无 Cookie 且 `trust_env=False` 的 Session；代理源下载及所有非推广点击请求仍走 WARP。
